# Calibration-Policy Split Check

## Split finding
- Canonical held-out test split is generated by `stratified_train_validation_test_split` and was kept unchanged.
- No persisted row-id split files were found; splits are deterministic from processed data and the central random seed.
- Existing main calibration pipeline uses train-only CV calibration (`CalibratedClassifierCV(cv=3)`), so that part does not use the validation split for calibration fitting.
- The caveat applies mainly to the imbalance-training revision script, where sigmoid/isotonic calibrators are fit on validation probabilities and threshold policies are also selected on that same validation split.

## Separated check applied
- For final selected non-SCRE model checks, the non-test development pool was repartitioned into `model_train=70%`, `calibration_val=15%`, and `policy_val=15%`.
- Model fitting used only `model_train`.
- Probability calibration used only `calibration_val`.
- Threshold/manual-review band selection used only `policy_val`.
- Held-out test was evaluated only after the policy was selected.

## SCRE limitation
- SCRE-Pareto/SCRE-Optimized rows were not fully recomputed in this small check because doing so would require re-running the full ensemble weight optimization and calibrated base-probability stack under the separated development split.
- Therefore SCRE keeps the caveat unless the full SCRE stack is re-run with nested calibration-policy validation.
